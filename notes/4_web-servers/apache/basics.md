**Apache это:** Самый старый и проверенный веб-сервер (1995 год). До сих пор рулит на shared-хостинге из-за `.htaccess`. Работает по принципу **«Один запрос — один поток/процесс»** (в классическом режиме Single/Multi-Process Model). Каждый пользователь может переопределить настройки сервера внутри своей папки, не перезагружая весь сервер. 

- **Слабость:** Дикая прожорливость к оперативной памяти (RAM) под высокой нагрузкой. Если к вам придет 10 000 одновременных клиентов, Apache попытается создать 10 000 тяжелых процессов, оперативка мгновенно кончится, и сервер упадет в своп.

**Основные концепции:**

- **Модули:** Почти всё в Apache — модули. Их можно подключать и отключать (`a2enmod`, `a2dismod`).
- **.htaccess:** Позволяет менять конфигурацию прямо из папки с сайтом, без доступа к основному конфигу. Удобно для пользователей, но замедляет работу (Apache каждый раз сканирует папки в поисках этих файлов).


В отличие от Nginx, архитектура Apache исторически строилась вокруг **процессов и потоков операционной системы**. За то, как именно Apache будет обрабатывать входящие сетевые пакеты, отвечают модули **MPM (Multi-Processing Modules)**.

В любой операционной системе Linux Apache может работать в одном из трех режимах MPM (переключается заменой системного модуля):

1. MPM Prefork (Старый многопроцессный режим)

- **Как работает:** Классический режим «один запрос — один процесс». Apache при старте создает пул тяжелых независимых процессов операционной системы. Когда приходит клиент, один процесс полностью забирает его себе и блокируется до тех пор, пока клиент не скачает страницу.
- **Плюсы:** Абсолютная изоляция. Если один процесс упадет из-за кривого PHP-скрипта, остальные 99 процессов продолжат работать.
- **Минусы:** Огромное потребление RAM (проблема C10k). Каждый процесс весит по 30–50 МБ. Тысяча одновременных клиентов мгновенно съест всю оперативную память вашего моноблока Proxmox. В современных реалиях этот режим считается устаревшим.

2. MPM Worker (Многопоточный режим)

- **Как работает:** Гибридный режим. Apache запускает несколько процессов, но внутри каждого процесса плодит множество легких системных потоков (Threads). Один поток обслуживает одного клиента.
- **Плюсы:** Потребляет значительно меньше памяти, чем Prefork, так как потоки делят память внутри одного процесса.

1. MPM Event (Современный асинхронный режим)

- **Как работает:** Архитектурный ответ разработчиков Apache на вызов со стороны Nginx. Он устроен так же, как MPM Worker, но в него встроен **асинхронный слушатель событий (Event Loop)**.
- **В чем магия:** В режимах Prefork и Worker, если клиент скачал страницу, но соединение удерживается (Keep-Alive), поток Apache обязан сидеть и тупо «ждать» новые команды от этого клиента, оставаясь занятым. В режиме **MPM Event** выделенный поток-диспетчер держит Keep-Alive соединения через неблокирующие вызовы ядра, а рабочие потоки освобождаются и отдаются новым активным клиентам. Это делает современный Apache невероятно быстрым и легким.

#### Установка:

```bash
sudo apt update
sudo apt install apache2 -y
```

#### Структура конфигурационных файлов Apache

В дистрибутивах Ubuntu/Debian конфигурация Apache (`apache2`) разбита на структуру папок, которая управляется специальными CLI-утилитами:

```text
/etc/apache2/
├── apache2.conf        # Главный системный конфиг (аналог nginx.conf)
├── ports.conf          # Здесь жестко прописываются порты (Listen 80, Listen 8082)
├── mods-available/     # Все доступные модули (php, rewrite, ssl, proxy)
├── mods-enabled/       # Символические ссылки на АКТИВНЫЕ модули
├── sites-available/    # Конфиги ваших виртуальных хостов (VirtualHosts)
└── sites-enabled/      # Символические ссылки на запущенные сайты
```


#### Virtual Host (как server block в nginx):

```apache
<VirtualHost *:80>
ServerName example.com
ServerAlias www.example.com
DocumentRoot /var/www/example
ErrorLog ${APACHE_LOG_DIR}/error.log
CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>
```

#### Основные команды управления:

- `sudo a2enmod rewrite` — (Apache2 Enable Module) включить модуль (например, модуль перезаписи URL-адресов).
- `sudo a2dismod prefork` — отключить модуль
- `sudo a2ensite example.com.conf` — включить виртуальный хост
- `sudo a2dissite example.com.conf` — выключить
- `sudo apache2ctl -t` — проверка конфига
