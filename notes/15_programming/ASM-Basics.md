Язык ассемблера — это символическое представление машинного кода. Процессор понимает только цепочки бит (например, 01001000 10001001 11000011 ). Человеку читать и писать такое невозможно. 

Ассемблер заменяет двоичные команды понятными словами — мнемониками (например, вместо кучи бит мы пишем mov rax, rbx ). Каждая строчка ассемблерного текста практически один в один переводится в одну команду процессора.

Программа жестко разделяется на ключевые области (секции):

```
высокие адреса
+------------------+
|     stack        |  растёт вниз
+------------------+
|        |         |
|      heap        |  растёт вверх
+------------------+
|  .bss            |  нулевые данные (неинициализированные)
+------------------+
|  .data           |  инициализированные данные
+------------------+
|  .rodata         |  константы
+------------------+
|  .text           |  КОД (read + execute)
+------------------+
низкие адреса
```

#### Section `.data`

Здесь объявляются переменные, у которых **есть начальное значение**. Они занимают место внутри готового скомпилированного файла.

Директивы выделения памяти: 
`db` (define byte - 1 байт)
`dw` (define word - 2 байта)
`dd` (define double word - 4 байта)
`dq` (define quad word - 8 байт)

Директива **`equ`** (`len equ $ - msg`). Она создает текстовую константу (алиас числу). Тогда `mov rdx, len` превратится на этапе компиляции в обычное `mov rdx, 6`. В отличае от директив выделения памяти, она хранит не адрес, а значение.

```s
section .data
	age db 25                       ; Выделен 1 байт памяти, там хранится число 25 
	year dw 2026                    ; Выделено 2 байта под число 2026 
	pi_code dd 314159               ; Выделено 4 байта 
	big_num dq 12345678901234       ; Выделено 8 байт (размер регистра x64)
	msg db "Hello, Student!", 10, 0

Строка - это просто последовательность одиночных байт (ASCII кодов символов ; 10 - код символа перевода строки (\n), 0 - терминальный ноль (конец строки)
```

В ассемблере NASM символ **`$` означает текущий адрес в памяти** (адрес той строки кода, на которой этот символ встречен). Поскольку данные в секции `.data` или `.rodata` идут в памяти друг за другом, адрес `$` (сразу после строки) минус адрес начала строки дает ровно количество байт в этой строке. **Этот расчет происходит на этапе компиляции**, а не во время работы программы, поэтому процессор не тратит время на подсчет.

```
section .data
    ; 1. Объявляем саму строку
    message     db  "Hello, World!", 10  ; 10 — это символ переноса строки (\n)
    
    ; 2. Вычисляем длину и записываем в другую переменную
    ; $ — это адрес прямо ЗДЕСЬ (сразу после "Hello, World!", 10)
    ; Вычитаем адрес начала строки (message) и получаем длину в байтах
    message_len dq  $ - message

section .text
    global _start

_start:
    ; Теперь мы можем использовать переменную message_len
    mov rdx, [message_len]   ; rdx = 14 (количество байт в строке)
    
    ; Пример вывода в Linux через системный вызов sys_write
    mov rax, 1              ; syscall: sys_write
    mov rdi, 1              ; дескриптор: stdout (экран)
    mov rsi, message        ; адрес строки
    ; rdx уже содержит длину, которую мы загрузили выше
    syscall

    ; Выход из программы
    mov rax, 60             ; syscall: sys_exit
    xor rdi, rdi            ; код возврата 0
    syscall

```

Важно помнить, **переменные хранят не значения, а адрес в памяти на значение**.

#### Section `.bss`

Здесь только **резервируется место** в оперативной памяти под будущие данные (например, под буфер для ввода текста). При запуске программы операционная система автоматически заполняет эту память нулями. Эти переменные **не занимают место на диске** в самом файле.

Директивы резервирования: `resb`, `resw`, `resd`, `resq` (аргумент - сколько нужно зарезервировать) и префиксы размера при заполнении во время выполнения.

`resb`, **`byte`** — 1 байт (8 бит) 
`resw`, **`word`** — 2 байта (16 бит)
`resd`, **`dword`** (Double Word) — 4 байта (32 бита)
`resq`, **`qword`** (Quad Word) — 8 байт (64 бита)

```
section .bss
	buffer resb 1024        ; Зарезервировать массив из 1024 одиночных байт
	user_id resd 1          ; Зарезервировать место под одно 4-байтовое число
	variable resb 1         ; Зарезервировать место под переменную весом 1 байт
```

После инициализации, заполнить данными такие переменные можно например с помощью инструкции `mov`:

```
mov byte [variable], 5   ; Записать ровно 1 байт
```

Передавать при этом название переменной нужно через квадратные скобки.


#### Section `.text`

```
section .text
	global _start
	
_start
	mov rax, 60
	mov rdi, 0
	syscall
```

В регистре `rax` указывается номер системного вызова, при `syscall`. 60 - номер системного вызова `sys_exit`. В `rdi` для вызова exit указывается код завершения программы.


#### Что такое знаковые и беззнаковые числа

На объявление переменных это никак не влияет, процессору все равно какие биты там будут храниться, разница проявляется во время

- **Беззнаковые числа (Unsigned)** — это только **положительные числа и ноль**. Старший бит используется как обычный разряд для увеличения емкости числа.
- **Знаковые числа (Signed)** — это и **положительные, и отрицательные числа**. Старший бит отводится под «знак»: если там `0`, число положительное, если `1` — отрицательное.

Наглядный пример (для 8-битного числа / 1 байт)

В одном байте ровно 8 ячеек для нулей и единиц. Но в зависимости от того, какой режим мы выбрали, этот байт будет означать совершенно разные вещи:

|Режим|Минимальное значение|Максимальное значение|Что происходит со старшим битом?|
|---|---|---|---|
|**Беззнаковый (Unsigned)**|`0` (все биты `0`)|`255` (все биты `1`)|Работает как числовой разряд (2⁷ = 128).|
|**Знаковый (Signed)**|`-128`|`+127`|**Хранит знак**. `0` — плюс, `1` — минус.|
Возьмем байт `11111111` (все единицы):

- Если процессор считает его **беззнаковым**, то 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = **255**
- Если процессор считает его **знаковым**, то первая единица говорит, что это минус, а по правилам дополнительного кода (Two's Complement) это значение равно **-1**.

Для самого процессора в регистрах лежат просто биты. Он не знает, знак это или нет, пока вы не вызовете конкретную инструкцию. Именно поэтому в x86-64 для условных переходов есть разделение:

1. **Для беззнаковых чисел** используются команды **`ja`** (Above — выше) и **`jb`** (Below — ниже).
2. **Для знаковых чисел** используются команды **`jg`** (Greater — больше) и **`jl`** (Less — меньше).

**Что будет, если перепутать?**  
Если в регистре `rax` лежит число `-1` (`1111...1111`), а в `rbx` лежит число `5` (`0000...0101`):

- Сравнение для **знаковых** чисел (`jl`) скажет, что `rax < rbx` (ведь -1 < 5).
- Сравнение для **беззнаковых** чисел (`jb`) скажет, что `rax > rbx` (ведь процессор увидит число 18 446 744 073 709 551 615, которое явно больше пяти).

Как работать с памятью: Важнейшее правило квадратных скобок `[]` 
Имя переменной в коде ассемблера — это просто символическое имя адреса в RAM. 
- Без скобок: `mov rax, age` — Процессор скопирует в регистр `RAX` числовой адрес (указатель), где в памяти лежит переменная `0x402005` ). 
- В квадратных скобках: age (например, адрес mov al, `[age]` — Процессор пойдет по адресу age в оперативную память, возьмет значение, которое там лежит (число 25), и скопирует его в регистр `al` . 

Правило соответствия размеров: Размеры регистра и ячейки памяти в одной команде обязаны совпадать

```
mov eax, [age]  ; ошибка, разрядность не совпадает. eax - это 4 байта, age - 1.
mov al, [age]   ; правильно. al - 1 байт, из памяти читается 1 байт. 
mov ebx, [year] ; ошибка ebx - 4 байта, year - dw (2 байта). 
```

Если нужно перенести значение из меньшей ячейки в больший регистр, используются специальные команды с расширением нулями или знаком: или `movsx`. Пример: 

`movzx eax, byte [age]` — прочитает 1 байт из памяти и заполнит оставшиеся 3 байта регистра eax нулями.

#### Регистр флагов (`RFLAGS`)

Регистр `RFLAGS` содержит биты состояний, которые автоматически обновляются после выполнения арифметических и логических операций (`add`, `sub`, `and`, `cmp`, `inc`, `dec` и др.). Инструкции вроде `mov` или `lea` флаги **не меняют**.
- **`ZF` (Zero Flag — флаг нуля):** устанавливается в `1`, если результат операции равен `0`. 
- **`SF` (Sign Flag — флаг знака):** равен старшему биту результата (копирует знаковый бит: `1` для отрицательных чисел, `0` для положительных).
- **`CF` (Carry Flag — флаг переноса):** фиксирует перенос или заем при операциях с _беззнаковыми_ числами (например, если результат вычитания ушел в «минус» в unsigned-логике).
- **`OF` (Overflow Flag — флаг переполнения):** фиксирует переполнение при операциях со _знаковыми_ числами (когда результат не помещается в разрядную сетку со знаком).


#### Сравнение перед переходом (`cmp` и `test`)

Ветвления и циклы почти всегда начинаются с подготовительной инструкции, которая выставляет флаги:
- **`cmp a, b`** (Compare) — выполняет внутреннее вычитание `a - b` (результат никуда не записывается), но настраивает флаги `ZF`, `SF`, `CF`, `OF`.
- **`test a, b`** — выполняет побитовое `AND` (результат отбрасывается), полезно для проверки регистра на нуль (`test rax, rax`)
- Инструкция **`xor`** выполняет операцию **побитового исключающего ИЛИ** (eXclusive OR) между двумя операндами и записывает результат в первый из них.

В ассемблере она чаще всего применяется в двух целях:

1. **Обнуление регистров (самый частый кейс):**  
    Команда `xor rax, rax` — это стандартный и самый быстрый способ записать в регистр ноль. Поскольку `один XOR один = 0` и `ноль XOR ноль = 0`, число, сравненное само с собой, всегда дает `0`. Это работает быстрее и занимает меньше байт в машинном коде, чем `mov rax, 0`.
2. **Побитовое инвертирование по маске:**  
    Если нужно изменить конкретные биты числа на противоположные (было `0` — стало `1`, было `1` — стало `0`), `xor` делает это с теми битами, где в маске стоят единицы.

```
section .data
    ; Мы объявили две абсолютно одинаковые переменные по 1 байту.
    ; В памяти компьютера числа 255 и -1 выглядят идентично: 11111111 (бинарно)
    number1  db  255
    number2  db  -1

section .text
    global _start

_start:
    ; Загружаем значения в регистры
    mov al, [number1]   ; al = 11111111
    mov bl, [number2]   ; bl = 11111111

    ; Сравниваем их
    cmp al, bl          ; Процессор вычитает их, флаг нуля ZF станет равен 1 (они равны!)

    ; --- ВОТ ЗДЕСЬ РЕШАЕТСЯ, ЗНАКОВЫЕ ОНИ ИЛИ НЕТ ---

    ; Вариант 1: Мы работаем с ними как с БЕЗЗНАКОВЫМИ
    ja .above           ; Прыгнет, если AL > BL (как беззнаковые: 255 > 255 - ложь, не прыгнет)

    ; Вариант 2: Мы работаем с ними как со ЗНАКОВЫМИ
    jg .greater         ; Прыгнет, если AL > BL (как знаковые: -1 > -1 - ложь, не прыгнет)

```


#### Инструкции переходов: переходы бывают безусловными и условными.

>Безусловный переход

- **`jmp метка`** — всегда передает управление на указанную метку (эквивалент `goto`).

>Условные переходы (по значению флагов)

Условия делятся на **беззнаковые** и **знаковые**: 

Для чисел со знаком (Signed):
- `je` / `jz` — равно / ноль (`ZF = 1`)
- `jne` / `jnz` — не равно / не ноль (`ZF = 0`)
- `jl` — меньше со знаком (`SF ≠ OF`)
- `jle` — меньше или равно со знаком (`ZF = 1` или `SF ≠ OF`)
- `jg` — больше со знаком (`ZF = 0` и `SF = OF`)
- `jge` — больше или равно со знаком (`SF = OF`)

Для чисел без знака (Unsigned):
- `jb` / `jc` — меньше (ниже) / есть перенос (`CF = 1`)
- `jbe` — меньше или равно (`CF = 1` или `ZF = 1`)
- `ja` — больше (выше) (`CF = 0` и `ZF = 0`)
- `jae` — больше или равно (`CF = 0`) 


#### Ветвления (структуры типа `if / else`)

На уровне ассемблера ветвление собирается через `cmp` + условный переход + метки:

```nasm
    cmp rax, 10
    jg  .greater      ; если rax > 10, прыгаем на .greater

    ; --- ветка 'иначе' (rax <= 10) ---
    mov rbx, 0
    jmp .endif        ; пропускаем ветку greater

.greater:
    ; --- ветка 'если' (rax > 10) ---
    mov rbx, 1

.endif:
    ; продолжение кода
```


#### Циклы (`loop` и связка `cmp` + `jmp`)

Цикл организуется либо через счетчик и инструкцию `loop`, либо (чаще в современном x86-64) через явное сравнение и условный переход. 

Пример цикла со счетчиком в `rcx` (сумма от 1 до 10):

```nasm
    xor rax, rax        ; rax = 0 (аккумулятор)
    mov rcx, 10         ; счетчик цикла rcx = 10

.loop_start:
    add rax, rcx        ; прибавляем счетчик к сумме
    dec rcx             ; уменьшаем rcx на 1
    jnz .loop_start     ; пока rcx != 0 (ZF == 0), повторяем
```

### Наглядный пример ассембли кода

```nasm
section .data
    ; Объявляем массив из 5 знаковых 64-битных чисел (квадслова - qword)
    array    dq  5, -3, 12, 0, -1
    ; Длина массива (5 элементов)
    array_len dq  5

section .text
    global _start

_start:
    ; --- 1. Подготовка (Инициализация регистров) ---
    xor rax, rax        ; rax = 0. Здесь мы будем копить сумму (аккумулятор)
    xor rbx, rbx        ; rbx = 0. Это будет наш индекс в массиве (i = 0)
    mov rcx, [array_len]; rcx = 5. Счетчик цикла (сколько элементов осталось проверить)

.loop_start:
    ; --- 2. Проверка условия завершения цикла ---
    test rcx, rcx       ; Проверяем, равен ли rcx нулю (выполняет побитовое AND)
    jz .loop_end        ; Если ZF=1 (то есть rcx == 0), выходим из цикла

    ; --- 3. Чтение элемента и проверка условия (ветвление 'if') ---
    ; Читаем элемент: array + rbx * 8 (умножаем на 8, так как каждый qword занимает 8 байт)
    mov rdx, [array + rbx * 8]

    cmp rdx, 0          ; Сравниваем текущее число с нулем
    jle .skip_element   ; Если число <= 0 (знаковое сравнение), прыгаем на .skip_element
                        ; В этот момент флаги SF и OF подсказали процессору, что число отрицательное

    ; --- 4. Тело ветвления (выполняется, только если число > 0) ---
    add rax, rdx        ; Добавляем положительное число к нашей сумме в rax

.skip_element:
    ; --- 5. Шаг цикла (инкремент индекса и декремент счетчика) ---
    inc rbx             ; Переходим к следующему индексу (i++)
    dec rcx             ; Уменьшаем счетчик оставшихся элементов (rcx--)
    jmp .loop_start     ; Безусловный переход в начало цикла на проверку

.loop_end:
    ; --- 6. Финал ---
    ; В этой точке в регистре rax находится итоговая сумма: 5 + 12 = 17 (0x11 в шестнадцатеричной системе)
    
    ; Стандартный выход из программы в Linux x86-64 через syscall
    mov rdi, rax        ; Передаем сумму как код возврата программы (можно проверить через echo $?)
    mov rax, 60         ; Номер системного вызова sys_exit
    syscall
```

### Syscalls 

#### `Write` (Номер вызова `1`), параметры:

- `rdi` — Номер дескриптора, `1` — стандартный вывод.
- `rsi` — Адрес буфера с выводом
- `rdx` — Размер буфера, обязательно передавать числом, а не адресом, для этого переменная с размером должна создаваться через `equ`

#### `Exit` (Номер вызова `60`), параметры:

- `rdi` — Код завершения процесса, например `0` для успешного завершения.
