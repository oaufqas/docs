Управление виртуальными машинами в Proxmox VE — это то, ради чего и создавалась эта платформа. Под капотом здесь работает связка **[[hardware-virtualization|KVM/QEMU]]**, но вместо написания многострочных bash-команд вы получаете мощную систему оркестрации

#### Устройство менеджмента виртуальных машин

Каждая виртуалка имеет свой уникальный цифровой идентификатор — **VMID** (например, `100`, `101`, `200`). Этот ID используется везде: в именах файлов дисков, в коде Terraform и в консольных командах.

Настройки виртуалок хранятся в файловой системе `/etc/pve` (FUSE в оперативной памяти). Конфиг машины с VMID `100` лежит в обычном текстовом файле:

```bash
cat /etc/pve/qemu-server/100.conf
```

Если вы измените этот текстовый файл руками (например, допишете туда объем памяти), Proxmox мгновенно применит настройки. Это то, через что под капотом работает Terraform.

Директория где лежат образы виртуалок:

```bash
ls /var/lib/vz/template/iso/
/var/lib/vz/template/cache/ # Для LXC контейнеров
```

Главные утилиты управления через консоль (CLI):

- `qm start 100` — запустить виртуалку.
- `qm stop 100` — жестко выключить (аналог выдергивания кабеля из розетки).
- `qm shutdown 100` — мягко послать сигнал ACPI на выключение ОС.
- `qm status 100` — проверить состояние машины

#### Пример установки виртуальной машины

Для создания виртуальных машин, на сервере должен быть .iso образ операционной системы, либо можно указать url для установки, загрузать iso на proxmox сервер можно в веб-панели.

Мастер создания "Create VM"

Нажимаем синюю кнопку **Create VM** в правом верхнем углу и заполняем вкладку:

1. **General:** Указываем `VMID` (например, `100`) и понятное имя (Name: `k8s-master`).
2. **OS:** Выбираем наш скачанный ISO-образ из хранилища `local`.
3. **System:** Оставляем по умолчанию. Но для современных ОС (Windows 11, некоторые ядра Linux) здесь можно включить Qemu Agent.
4. **Disks (ДИСКИ):**
    - _Storage:_ Выбираем **`local-lvm`** (тонкий пулл LVM, размеченный при установке proxmox).
    - _Bus/Device:_ Вместо дефолтного IDE/SATA **всегда выбирайте SCSI**.
    - _Controller:_ Выберите **VirtIO SCSI**. Это включит паравиртуализацию (прямой быстрый доступ к SSD в обход эмуляции старых контроллеров).
5. **CPU:** Выставляем количество ядер.
    - _Type:_ Вместо `kvm64` **всегда выбирайте `host`**. Это пробросит все микрокоды реального процессора внутрь виртуалки, что ускорит компиляцию и работу.

**QEMU Guest Agent**

После того как вы установили Ubuntu внутри виртуалки, вы заметите, что во вкладке _Summary_ в Proxmox не отображается IP-адрес виртуалки, а кнопка _Shutdown_ в панели может не работать.

Это потому, что гипервизор снаружи не знает, что происходит внутри гостевой ОС. Чтобы подружить их, внутрь виртуалки нужно поставить **агента**.

```bash
sudo apt update && sudo apt install -y qemu-guest-agent

sudo systemctl enable --now qemu-guest-agent
```

#### Снапшоты и Клонирование

- **Snapshots (Снимки состояния):** Вы можете сделать снимок машины в любой момент во вкладке _Snapshots_. Поскольку ваши диски лежат на `LVM-Thin`, создание снимка занимает **0.1 секунды**. Вы можете за секунду откатиться назад.
- **Templates (Шаблоны):** Когда вы идеально настроили одну виртуалку Ubuntu (поставили докер, настроили сеть, обновили пакеты), вы можете кликнуть на нее правой кнопкой мыши и выбрать **Convert to Template (Превратить в шаблон)**. Машина заморозится и станет эталоном.


**Cloning (Клонирование):** Из этого шаблона вы можете мгновенно нарезать 10 одинаковых виртуалок с помощью функции _Clone_.

- Linked Clone (Связанный клон): Создается за 1 секунду, так как использует диск шаблона как основу (Read-Only), а внутрь новой виртуалки пишет только изменения. Экономит гигабайты на накопителе. Но при этом, если будет большая нагрузка на диск с нескольких Linked копий, они могут не выдержать. Поэтому для высоконагруженных систем лучше использовать Full Clone, а для низконагруженных LXC контейнер. Критическая зависимость от шаблона.

- Full Clone (Полное копирование): Для создания нужно время, как для создания виртуалки из образа. Создает независимую виртуальную машину с настройками шаблона.

#### Cloud-Init Templates

Создавать виртуалки в proxmox можно несколькими способами: 

1) Загружать ISO-image на сервер, установка виртуальной машины с нуля (ее настройка при установке ≈ 15 минут на одну машину). Потом ее конечно можно вынести в template и создавать подобных машин сколько угодно уже не так долго. Но при настройке в машину зашивается ip адрес (если статический) и в клонах это придется вручную менять.
2) Копировать виртуальную машину с template (Linked, Full), но каждую придется перенастраивать.
3) Cloud-Init почти тоже самое что и клонирование, но можно менять конфигурацию нужных параметров (сеть, юзеры, днс, ssh) из proxmox, а не в самой ос. Чтобы использовать cloud-init есть несколько способов:
	- Использование Cloud-Init images, которые можно использовать для proxmox.
