#### Прямая установка Proxmox VE (Загрузочная флешка)

Шаг 1. Подготовка флешки

1. Скачайте самый свежий ISO-образ **Proxmox VE** с официального сайта.
2. Скачайте бесплатную утилиту **Rufus** (или **BalenaEtcher**).
3. Вставьте флешку в основной ПК, откройте Rufus, выберите скачанный ISO-образ Proxmox.
4. **Важно:** Rufus может спросить режим записи. Выберите **Режим DD-образа**

Шаг 2. Запуск установки на физическом сервере

1. Вставьте готовую флешку в выключенный сервер. Подключение к интернету от роутера критически важно, Proxmox должен настроить сеть при установке.
2. Включите сервер и вызовите Boot Menu (обычно это `F12`, `F11`, `F8` или `Esc` в зависимости от производителя).
3. Выберите в списке флешку с образом.
4. Откроется приветственный экран Proxmox. **Install Proxmox VE (Graphical)**. (Отличий от Terminal UI нет, используется на компьютерах с проблемной графикой)

Шаг 3. Настройка в инсталляторе

1. **Target Harddisk:** Выбор носителя для установки системы. По умолчанию инсталлятор сотрет его полностью и создаст там структуру прав LVM/LVM-Thin.
2. **Password / Email:** Установка пароля для пользователя `root`.
3. **Management Network (СЕТЬ):** Инсталлятор сам увидит вашу сетевую карту и получит IP-адрес от роутера по DHCP, но можно задать ip адрес самостоятельно.

После установки, сервер будет доступен в сети для подключения по адресу, назначенному роутером или вручную на порту `8006`, на экране будет выведен адрес подключения, например `http://192.168.0.100:8006` - это адрес веб страницы управления сервером.

В моем случае было нужно сделать подключение сети по WI-FI карте (proxmox по умолчанию может работать только с проводным интернетом).

Для этого нужно поменять настройки сетевых инртерфейсов в `/etc/network/interfaces`, изначальный конфиг:

```
auto lo
iface lo inet loopback

iface nic0 inet manual

auto vmbr0
iface vmbr0 inet static
		address 192.168.0.167/24
		gateway 192.168.0.1
		bridge-ports nic0
		bridge-stp off
		bridge-fd 0

iface nic1 inet manual

source /etc/network.interfaces.d/*
```

Переделанный конфиг:

```
auto lo
iface lo inet loopback

iface nic0 inet manual
iface nic1 inet manual

# Настройка Wi-Fi карты (Выдача статического IP)
auto wlp1s0
iface wlp1s0 inet static
        address 192.168.0.167/24
        gateway 192.168.0.1
        wpa-conf /etc/wpa_supplicant/wpa_supplicant.conf

# Изолированный виртуальный мост для машин Kubernetes (Режим NAT)
auto vmbr0
iface vmbr0 inet static
        address 192.168.100.1/24
        bridge-ports none
        bridge-stp off
        bridge-fd 0
        # Включаем форвардинг пакетов в ядре, чтобы пакеты ходили между namespaces
        post-up echo 1 > /proc/sys/net/ipv4/ip_forward
        # Настраиваем iptables, чтобы выпускать виртуалки через Wi-Fi
        post-up iptables -t nat -A POSTROUTING -s '192.168.100.0/24' -o wlp1s0 -j MASQUERADE
        post-down iptables -t nat -D POSTROUTING -s '192.168.100.0/24' -o wlp1s0 -j MASQUERADE

source /etc/network/interfaces.d/*
```

По мимо настройки WI-FI карты, необходимо настроить маскарадинг (NAT) для виртуальных машин, они будут создаваться в виртуальной сети (не в локальной). Сам Proxmox внутри сети виртуалок получит постоянный IP **`192.168.100.1`**. Все виртуалки будут создаваться с адресами вроде `192.168.100.10`, `192.168.100.11` и указывать этот адрес в качестве шлюза. Ядро через `iptables` будет прозрачно перенаправлять их пакеты в интерфейс `wlp1s0`.

Чтобы достучаться напрямую в виртуалки через NAT, нужно указать в настройках роутера статический путь к ip сервера, чтобы пакеты от устройств в локальной сети летели так: 

```
ПК (..0.177) --> Роутер (..0.1) --> Сервер (..0.167) --> Виртуалки (..100.*)
```

#### Во время установки, proxmox размечает диск на несколько разделов, используя [[hardware-virtualization#LVM (Logical Volume Manager / Менеджер логических томов)|LVM]]:

Как видно из вывода, установлен один физический высокоскоростной диск **`nvme0n1`** размером 238.5 ГБ (его Major-номер `259` подтверждает, что это честный NVMe). Инсталлятор разбил его на три части:

1. **`nvme0n1p1` (1007 КБ):** Крошечный технический хвост, зарезервированный под таблицу разделов GPT.
2. **`nvme0n1p2` (1 ГБ):** Раздел EFI, смонтированный в `/boot/efi`. Сюда GRUB записал загрузочные файлы ядра, чтобы материнская плата моноблока могла запустить Proxmox при включении.
3. **`nvme0n1p3` (237.5 ГБ):** **Главная рабочая область**. Proxmox превратил этот раздел в **PV (Physical Volume)** и создал внутри него группу томов **`pve`** (Volume Group)

**Как распределена память внутри LVM группы `pve`**

Заглянем внутрь группы томов LVM. На базе 237.5 ГБ ядро нарезало несколько логических томов (`LV`):

- **`pve-swap` (7.5 ГБ):** Раздел подкачки (Swap). Если виртуалкам не хватит RAM, ядро начнет временно сбрасывать туда неиспользуемые страницы памяти.
- **`pve-root` (69.5 ГБ):** Это «жесткий диск» самого Proxmox (Debian). Он смонтирован в корень **`/`**. Команда `df -h` показывает, что система занимает там всего 4.2 ГБ, а 61 ГБ у вас абсолютно свободны.
- **`pve-data` (141.6 ГБ — LVM-Thin Пул):** **Самый главный элемент!** Стоит обратить внимание на `pve-data_tmeta` и `pve-data_tdata` в `lsblk`. Это метаданные и данные **тонкого пула LVM-Thin**. На пуле `pve-data` нет файловой системы, и он никуда не смонтирован. Это чистый "котел" блочной памяти, который будет использоваться при создании новых виртуалок, proxmox откусит от этого пула кусок памяти, необходимый виртуалке либо контейнеру. При этом память самой системы proxmox не используется, что дает большое приемущество в скорости

В выводе `df -h` есть строчка:

```text
/dev/fuse             128M   16K  128M   1% /etc/pve
```

Это уникальная фишка Proxmox — **Кластерная файловая система pmxcfs (Proxmox Cluster File System)**.  
Она работает через механизм **FUSE (Filesystem in Userspace)**. Папка `/etc/pve` физически не существует на диске. Это база данных настроек ваших будущих виртуалок, которая живет прямо в оперативной памяти ядра
