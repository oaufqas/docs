### DNS (Domain Name System)

Система, преобразующая удобные для человека доменные имена (например, `example.com`) в IP-адреса понятные компьютерам (`93.184.216.34`). Работает по протоколу UDP (порт 53), в некоторых случаях TCP (для больших ответов).

#### Процесс разрешения имени (рекурсивный)

1. Пользователь вводит `example.com`.
2. Запрос отправляется рекурсивному DNS-серверу (обычно провайдера).
3. Рекурсивный сервер проверяет кэш. Если нет, идёт к корневому серверу.
4. Корневой сервер отвечает адресами серверов .com.
5. Рекурсивный сервер спрашивает у сервера .com адрес авторитативного сервера для `example.com`.
6. Запрос к авторитативному серверу, который возвращает IP-адрес.
7. Ответ возвращается клиенту и кэшируется.


>Изменение dns записей локально на пк:

- **Linux**: `/etc/hosts`
- **Windows**: `C:\Windows\System32\drivers\etc\hosts`

#### Иерархия DNS:

- **Корневые серверы** (root) – 13 кластеров по всему миру. Отвечают за зоны верхнего уровня (TLD).
- **Серверы TLD (Top-Level Domain)** – отвечают за .com, .org, .ru и т.д.
- **Авторитативные серверы** – хранят записи для конкретных доменов.
- **Рекурсивные резолверы** – серверы провайдера или публичные (8.8.8.8), выполняющие запросы от имени клиента.


>Типы DNS-записей

- **A** – IPv4-адрес
- **AAAA** – IPv6-адрес
- **CNAME** – каноническое имя (алиас)
- **MX** – почтовый сервер (с приоритетом)
- **TXT** – произвольный текст (SPF, DKIM)
- **NS** – сервер имен для зоны
- **PTR** – обратная запись (IP → имя)
- **SOA** – Start of Authority (параметры зоны)

>Утилиты для диагностики

- **[[notes/1_linux/networking#**DNS-запросы (dig, nslookup)**|nslookup]]** – простой запрос
- **[[notes/1_linux/networking#**DNS-запросы (dig, nslookup)**|dig]]** – подробный вывод

#### Создание своего DNS-резолвера:


```bash
# 1. Устанавливаем dnsmasq
sudo apt update && sudo apt install -y dnsmasq

# 2. Отключаем дефолтный systemd-resolved, чтобы он не занимал порт 53
sudo systemctl stop systemd-resolved
sudo systemctl disable systemd-resolved
# Удаляем старую системную ссылку на resolv.conf
sudo rm /etc/resolv.conf
# Прописываем внешние DNS (например, Яндекс или Google), чтобы сам контейнер видел интернет
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf

# 3. Настраиваем dnsmasq
sudo nano /etc/dnsmasq.conf
```

В файл `/etc/dnsmasq.conf` добавить минимальный конфиг.

```bash
# Слушать на всех интерфейсах (включая наш IP 192.168.100.5)
listen-address=127.0.0.1,192.168.100.5

# Локальная доменная зона вашего кластера
domain=cluster.local
local=/cluster.local/

# Если dnsmasq не знает имя, он перенаправит запрос выше (в интернет)
server=8.8.8.8
server=1.1.1.1

# Включаем чтение локальных хостов
expand-hosts
```

Теперь зашейте карту вашей сети прямо в файл `/etc/hosts` **этого DNS-контейнера**:

```bash
sudo nano /etc/hosts
```

Добавьте туда жесткие IP-адреса вашей инфраструктуры:

```text
192.168.100.10 control-plane control-plane.kubernetes.local
192.168.100.11 node-0 node-0.cluster.local
192.168.100.12 node-1 node-1.cluster.local
```

Перезапустите службу DNS:

```bash
sudo systemctl restart dnsmasq
sudo systemctl enable dnsmasq
```

_Всё! На порту `192.168.100.5:53` у вас заработал полноценный DNS-сервер._


#### FQDN (Fully Qualified Domain Name) — Полное доменное имя

**FQDN — это абсолютно полное и уникальное имя устройства в иерархии DNS.** Оно состоит из всех уровней доменов, заканчивая корневым доменом (который обычно не пишут, но подразумевают как точку `.` в конце).

**Структура FQDN (снизу вверх):**

```text
hostname.subdomain.domain.tld.
│        │         │      │
│        │         │      └── Домен верхнего уровня (TLD), например .com, .local
│        │         └── Основной домен, например, google, yandex
│        └── Поддомен (может быть несколько, например, api, mail)
└── Имя хоста (конкретного устройства)
```

**Примеры:**

- `mail.google.com.` — FQDN для почтового сервера Google.
- `node-0.cluster.local.` — FQDN для вашего worker-узла Kubernetes.

**Короткое имя (hostname)** — это просто первая часть FQDN: `mail` или `node-0`.

Зачем нужны FQDN?

1. **Уникальность**: FQDN гарантирует, что в мировом или локальном пространстве имен не будет конфликтов. В мире может быть много серверов `web`, но только один `web.mycompany.com.`.
2. **Иерархия**: Структура FQDN позволяет делегировать ответственность за зоны. Например, вы можете управлять зоной `kubernetes.local` внутри своей компании, не влияя на глобальный DNS.
3. **Поиск (Search Domains)**: Если вы используете короткое имя (`node-0`), операционная система автоматически "примеряет" к нему поисковые домены (`kubernetes.local`), чтобы превратить его в FQDN.

#### Как работает DNS-резолвер в Linux

В Linux за разрешение имен отвечает система **glibc** (GNU C Library), которая использует несколько источников для преобразования имени в IP-адрес. Эти источники и их порядок определяются файлом **`/etc/nsswitch.conf`** (Name Service Switch). Обычно там есть строка:

```bash
hosts: files dns
```

Это означает, что при попытке разрешить имя, система сначала проверит **локальные файлы**, а потом уже обратится к **DNS-серверу**.


>1) `/etc/hosts` (локальный файл имен) - это самый первый источник. Все записи в нем имеют **высший приоритет**. Синтаксис простой:


```bash
<IP-адрес> <FQDN> [псевдонимы]
```

**Пример:**

```bash
127.0.0.1 localhost
192.168.100.10 control-plane.kubernetes.local control-plane
192.168.100.11 node-0.kubernetes.local node-0
```

**Как это работает:**

- Когда вы вводите `ping node-0`, система сначала ищет `node-0` в `/etc/hosts`.
- Если находит, использует IP сразу, даже не обращаясь к DNS.
- Если не находит — переходит к следующему шагу.


>2) `/etc/resolv.conf` (конфигурация DNS-резолвера) - этот файл указывает, к каким DNS-серверам обращаться и как они должны работать.  Он выглядит примерно так:


```bash
nameserver 192.168.100.20
search kubernetes.local
options edns0 trust-ad
```

**Разберем параметры:**

|Параметр|Назначение|
|---|---|
|**`nameserver`**|IP-адрес DNS-сервера (может быть несколько).|
|**`search`**|Список доменов, которые будут подставляться к коротким именам.|
|**`options`**|Дополнительные настройки (например, `edns0` для больших пакетов).|

Если локально (`/etc/hosts`) можно написать короткий домен (например одно слово - `node-1`), и оно будет резолвится, то dns сервер должен отдавать FQDN, либо мировой (`.com`, `.org` и др) либо настроить локальную DNS-зону.

Почему система будет резолвить `google.com`, но не `node-0`?

[Google.com](https://google.com/) (FQDN)

Имя `google.com` — это **полное доменное имя (FQDN)**. Оно содержит точку `.`, и система понимает: _"Это полное имя, искать его надо как есть"_.

1. Проверяет `/etc/hosts` — нет.
2. Обращается к DNS-серверу (192.168.100.20) с запросом `google.com`.
3. DNS-сервер, не найдя зону `google.com` локально, идет по иерархии DNS (корневые серверы → TLD `.com` → авторитативный сервер).
4. Возвращает IP — вы получаете доступ.

node-0 (короткое имя, не FQDN)

Имя `node-0` **не является** FQDN — в нем нет точки `.`. Система пытается его **преобразовать**.

1. Проверяет `/etc/hosts` (там его может и не быть, если вы не добавили запись).
2. Поскольку в `/etc/hosts` нет `node-0`, система смотрит на параметр `search` в `/etc/resolv.conf`.
3. У вас там написано `search kubernetes.local`. Значит, система будет пытаться подставлять этот домен к имени `node-0`.
4. Она последовательно пробует: `node-0.kubernetes.local`.
5. **Если** ваш DNS-сервер (192.168.100.20) знает запись для `node-0.kubernetes.local` — он вернет IP.
6. **Если** не знает — вернет ошибку `NXDOMAIN` (нет такой записи).


**Золотое правило:** Если вы используете короткие имена внутри локальной сети, всегда либо:

1. Добавляйте их в `/etc/hosts` на всех машинах.

2. Настраивайте **зоны поиска** (`search`) и создавайте соответствующие записи на вашем DNS-сервере.
