## Exporter - это мост между системой и Prometheus

- Это отдельный процесс или агент, который собирает метрики из приложения, системы или сервиса и преобразует их в формат, понятный прометеусу ("/metrics")

### Наиболее популярные Exporters:

 - `node_exporter` - Метрики хоста Linux (CPU, память, диски, сеть) -- `1860`
 - `blackbox_exporter` - Проверка доступности (ping, HTTP, TCP) -- `7587`
 - `postgres/mysql_exporter` - Состояние PostgreSQL/MySQL -- (PG)`9628` (My) `7362`
 - `jmx_exporter` - Java-приложения
 - `nginx VTS Exporter` - Метрики Nginx -- `2949`
 - `redis_exporter` - Метрики Redis -- `763`
 - `kube_state_metrics` - Состояние Kubernetes -- `13332`
 - `cAdvisor` - Контейнеры docker -- `14282`
 - `Windows Exporter` - Железо Windows (аналог node_exporter) -- `14694`

Если нужно мониторить сервис, у которого нет экспортера, можно использовать библиотеку SDK внутри кода (python, go, java), чтобы сервис сам отдавал метрики на эндпоинт `/metrics`, если изменять код нельзя, то можно написать свой скрипт-экспортер на Python.

#### Использование exporters в yaml конфиге:

```yaml
scrape_configs:
  - job_name: 'linux-servers'
    static_configs:
      - targets: ['192.168.1.10:9100', '192.168.1.11:9100']

  - job_name: 'containers-metrics'
    metrics_path: '/'
    static_configs:
      - targets: ['localhost:8080'] # Порт cAdvisor по умолчанию
```

`metrics_path` - эндпоинт, по которому прометеус будет ходить и забирать метрики, по умолчанию это `/metrics`.

После установки экспортера, все метрики, которые он мониторит и собирает, будут доступны как Web страница под определенным HTTP портом (у каждого свой обычно)

Если IP сервера 10.0.0.1, node exporter публикует метрики на HTTP Port 9100:
- По адресу `http://10.0.0.1:9100` будет выведена информация про exporter
- По адресу `http://10.0.0.1:9100/metrics` будут сами метрики списком

### Написание своего exporter для prometheus на C++ без использования библиотек

Будем писать HTTP-сервер для стандартной PULL модели, когда prometheus сам забирает метрики из приложения. Он с заданной периодичностью (например, каждые 15 секунд) отправляет стандартный **HTTP GET** запрос на ваш сервер (обычно на эндпоинт `/metrics`), а ваше приложение должно моментально выдать текущее состояние всех метрик.

Это означает, что приложение **не должно ничего отправлять «по событию» во внешнюю среду**. Его задача — непрерывно обновлять метрики внутри своей памяти, а в момент прихода HTTP-запроса просто сериализовать их в текст и отдать.

Prometheus использует текстовый формат Line Exposition Format. Каждая метрика описывается одной или несколькими строками. Структура одной метрики:

```text
# HELP имя_метрики Человекочитаемое описание того, что это такое
# TYPE имя_метрики тип_метрики (counter, gauge, histogram, summary)
имя_метрики{лейбл1="значение1",лейбл2="значение2"} числовое_значение
```

- **Служебные строки (`# HELP` и `# TYPE`):** Не обязательны, но очень рекомендуются. Название метрики в них должно строго совпадать с самой метрикой.
- **Лейблы (теги):** Помещаются в фигурные скобки `{}` сразу после имени метрики без пробелов. Ключ и значение разделяются знаком `=`, а строковое значение **обязательно** берется в двойные кавычки `""`. Несколько лейблов разделяются запятыми.
- **Значение:** Отделяется от метрики (или от закрывающей фигурной скобки) **одним пробелом**. Это должно быть число (целое или с плавающей точкой через `.` , например `10` или `36.6`).
- **Конец строки:** Каждая метрика должна заканчиваться символом переноса строки `\n`. В самом конце всего HTTP-ответа тоже должна быть пустая строка.

```
# HELP http_requests_total Total number of processed HTTP requests.
# TYPE http_requests_total counter
http_requests_total{method="GET",status="200"} 1053
http_requests_total{method="POST",status="500"} 2

# HELP system_memory_usage_bytes Current memory usage in bytes.
# TYPE system_memory_usage_bytes gauge
system_memory_usage_bytes 4294967296
```
